## 📌 项目定位与角色（FDE 模式主导）

**JJZN 企业级综合数字化 ERP 平台** 是面向现代工程、制造与数字化企业打造的**全链路一体化运营与生产管控平台**。

在该项目中，我承担了 **FDE（Forward Deployed Engineer，前向部署工程师）** 的复合型核心角色。开发过程中最大的特色在于**直接对接公司高层与核心业务部门的真实需求**——没有专职产品经理在中间充当传话筒或编写详尽 PRD，几乎所有业务模块**直接从公司的原始经营诉求与管理痛点切入开发**：

- **直接对接公司核心需求**：直接与公司决策层、各业务线主管对话，深度理解公司在成本控制、工程进度把控、供应链周转等层面的战略目标与运营卡点；
- **从原始需求直接推演系统模型**：将公司提出的粗颗粒度想法、口头管理意图与痛点草案，凭借技术与业务双重视角，独立推演为严密的数据状态机、审批流转逻辑与交互原型；
- **全盘独立工程交付**：不仅在 **PC 浏览器端**承载超高复杂度的业务数据流转与审批，还扩展了针对仓储单据批量输出的 **Electron 桌面端**，以及面向现场工程师快速作业打卡的 **移动现场端（H5 / 微信小程序）**，高效闭环落地。

## 🏗️ 业务版图与核心子系统全景

系统涵盖 **16 个高度联动的核心业务子模块**，消除了企业内部的信息孤岛：

```
                ┌─────────────────────────────────────────────────────┐
                │             经营驾驶舱 (Dashboard) & 经营决策分析      │
                └─────────────────────────┬───────────────────────────┘
                                          │ 状态联动 & 数据回流
┌────────────────────┐    ┌───────────────┴──────────────┐    ┌────────────────────┐
│ 销售与合同管理     │ ➔  │ 项目全生命周期管控 (预算/概算/落地) │ ➔  │ 采购与供应链履约   │
└────────────────────┘    └───────────────┬──────────────┘    └─────────┬──────────┘
                                          │                             │
┌────────────────────┐    ┌───────────────┴──────────────┐    ┌─────────┴──────────┐
│ 移动端现场运维作业 │ ➔  │ 智能仓储中心 (期初导入/出入库)  │ ➔  │ 人事管理与 KPI 绩效 │
└────────────────────┘    └──────────────────────────────┘    └────────────────────┘
```

### 1. 项目全生命周期管控系统（核心资产）
- **前期预算筹备**：人工、外包、材料三项清单编制，项目经理初审与成本部门终审后固化基准；
- **执行概算**：时效与金额双维度概算并行，确认后自动同步生成执行落地任务副本；
- **落地执行与偏差追踪**：实时追踪实际消耗工时与物资，自动比对概算，超出偏差阈值强制触发原因提报与逐级复核；
- **验收与结项**：与下游采购、外包任务进度双向绑定，闭环回写。

### 2. 智能仓储与物料流转
- **期初库存批量导入**：支持大规模物料档案批量校验、阶梯导入与格式防错；
- **出入库与损耗核算**：配方管理、出入库动态过账与实时盘点，联动移动端扫码高效出库。

### 3. 现场运维作业与移动端（uni-app）
- 面向现场工程人员，支持**工作流审批移动端流转**、**现场照片防伪水印添加**、凭证及服务密钥对接。

### 4. 人事绩效与薪资考核
- KPI 绩效多维评分、月份优先考核排序、绩效表单动态导出与格式化打印。

## ⚙️ 核心技术突破：自研轻量级工作流引擎设计（vs 传统 BPM）

在工程与制造型 ERP 体系中，**工作流审批**是串联“立项预算 -> 采购会签 -> 物料领料 -> 验收结项”的核心运转中枢。针对该底层核心，在技术选型与系统架构上经历了一次关键的自主攻坚：

### 1. 架构选型复盘：为什么主动舍弃传统 BPM / BPMN 2.0？

立项初期，团队曾评估过业内成熟的开源 BPM 方案（如 Flowable / Camunda 配套 bpmn-js），但在深入结合本 ERP 的实际业务痛点与用户群体后，我主动提出并推动了**“摒弃重型 BPM，自研轻量级卡片式流程引擎”**的架构决策：

| 评估维度 | 传统 BPMN 2.0 规范 (如 bpmn-js) | 自研卡片流程树引擎 (本项目落地) | 架构选型与业务契合结论 |
| :--- | :--- | :--- | :--- |
| **概念复杂度与学习曲线** | 图元近百种（排他/并行网关、边界事件、序列流、子流程等），业务与管理人员使用门槛极高 | 收敛为「发起人、审批人、条件分支、抄送人、业务触发器」5 类标准卡片 | **自研胜出**：零门槛开箱即用，交互友好直观 |
| **拓扑结构与防错成本** | 自由网状连线（Graph-based），极易产生悬空分支、孤立节点与不可达回路，需复杂的环路死锁检测 | **单向树状 AST（Tree-based DAG）**，结构自顶向下天然无环、强制闭合 | **自研胜出**：从数据结构源头杜绝非法逻辑回路 |
| **跨端自适应 (PC + uni-app)** | 无限画布自由拖拽，在移动端（手机屏幕、微信小程序）几乎无法优雅缩放与操作，体验严重割裂 | 仿主流现代协同工具的垂直卡片流式布局，PC 与移动端均能天然自适应 | **自研胜出**：一次编排，跨端无缝高保真还原 |
| **与业务表单的绑定深度** | 流程引擎与表单引擎往往是割裂的独立体系，跨系统注入字段级读写权限与业务副作用极其臃肿 | **流程节点与 Schema 字段权限矩阵深度内嵌**，各节点可直接控制字段的读写/隐藏 | **自研胜出**：与动态表单天然同源，状态响应极速 |

### 2. 流程引擎的核心架构与工程实现

我主导设计并独立完成了该流程引擎从 **AST 数据模型、Web 可视化编排器、安全条件求值沙箱、到移动端轻量运行时** 的完整闭环：

#### ① 树状抽象语法树（AST）数据结构设计
将复杂的网状流转收敛为单向嵌套的树状 JSON 结构，天然杜绝死锁并具备极高序列化友好性：

```ts
// 核心节点类型抽象
type WorkflowNodeType = 'start' | 'approver' | 'conditionBranch' | 'notifier' | 'trigger';

interface WorkflowNode {
  nodeId: string;
  nodeName: string;
  type: WorkflowNodeType;
  // 审批人规则：指定成员 / 角色 / 连续多级部门主管 / 发起人自选
  approvalConfig?: ApprovalRuleConfig;
  // 字段级动态权限矩阵（只读/可编辑/隐藏/必填）
  fieldPermissions?: Record<string, 'READONLY' | 'EDITABLE' | 'HIDDEN' | 'REQUIRED'>;
  // 条件分支路由组（当节点类型为 conditionBranch 时）
  conditionBranches?: ConditionBranch[];
  // 单向流转下游指针（形成严格有向无环流程链）
  childNode?: WorkflowNode | null;
}
```

#### ② 可视化低代码编排器（Web 流程设计器）
- **递归树渲染引擎**：基于 Vue 3 递归组件机制，自顶向下递归渲染节点卡片与连接线。在任意两节点之间的连接管线上动态挂载 `+` 插入手柄，支持一键追加审批人、抄送人或分支条件组；
- **分支自动弹性对称排版**：纯 CSS Grid/Flex 配合自动连线算法，随着条件分支层级增加自动向左右平滑延展，并保持分支汇聚点的精准闭合对齐；
- **发布态静态分析与校验**：在流程保存与发布前，执行 AST 静态分析器，快速校验空审批人、无兜底条件分支、条件表达式语法异常等边界隐患，阻断脏配置入库。

#### ③ 动态条件表达式安全求值沙箱
- 业务分支往往依赖单据表单的动态输入（如 `formData.budgetAmount > 100000 && formData.projectType === 'ENGINEERING'`）；
- 为避免 `eval` 或 `new Function` 带来的 XSS 注入风险与内存泄漏，自研了**轻量级条件分词与求值沙箱**：
  - 支持常用关系运算（`>`、`<`、`==`、`in`、`between`）与逻辑组合（`&&`、`||`）；
  - 运行时构建只读 Proxy 数据上下文，在纳秒级完成条件命中判定，自动决定下游审批路由。

#### ④ 字段级权限矩阵与业务副作用闭环
- **动态表单权限联动**：表单组件通过注入当前审批节点的 `fieldPermissions` 上下文，自适应切换各字段的只读文本渲染、禁用态或可编辑校验规则，杜绝“某审核人越权篡改底表数据”的安全隐患；
- **业务触发器（Trigger Node）**：在关键审批通过节点支持挂载微任务钩子（如：结项审批通过后自动触发下游“物资锁库释放”与“工时归档”），实现纯业务逻辑与工作流状态转移的无缝解耦。

#### ⑤ 跨端渲染与状态同步（PC + uni-app 跨端复用）
- 将流程 AST 的解析、节点激活状态判定、进度百分比计算等底层逻辑封装在 `@jjzn/workflow-core` 通用模块中；
- 移动现场端（uni-app）无需引入重型设计器代码，直接复用轻量只读流水线渲染器，实现审批历史、当前待办卡片、移动端加签与快捷退回的毫秒级即时响应。

## 🛠️ 工程化架构与独立落地亮点

面对体量庞大、页面众多的复杂系统，通过规范的工程化手段保障单人维护全套系统的可持续性：

### 1. Monorepo 体系与共享能力提炼
- 采用 **pnpm workspace** 治理整个前端代码库，将通用的业务逻辑、类型定义与请求拦截统一抽离至 `@jjzn/web-utils`；
- 封装通用的 `@jjzn/web-ui` 组件库（基于 Naive UI），统一处理复杂数据表格（服务端分页、排序、搜索重置）、通用模态弹窗与表单片段，大幅降低后续重复业务的开发成本。

### 2. 深度原子化样式（UnoCSS）与设计 Token 规范
- 摒弃传统冗长的 scoped CSS，全面引入 UnoCSS，结合业务需求定制专有的 Uno Shortcuts 与主题 Token；
- 避免页面局部覆盖造成的主题污染，样式体积大幅精简，样式重构与维护成本下降 50% 以上。

### 3. 多端扩展：Electron 硬件桥接与 uni-app 跨端
- **桌面端**：基于 Electron 封装桌面外壳，打通系统底层打印 API，实现出入库单、业务凭据的批量静默原生出票，避免频繁弹窗影响效率；
- **移动端**：基于 uni-app (Vue3 + Vite) 独立交付 H5 与微信小程序，支持现场水印拍照与快速审核。

### 4. FDE 交付范式：直接对接公司需求，由原始诉求驱动全链路闭环

在传统企业数字化项目中，研发人员往往处于流水线最末端，被动接受经过多层传话、失真严重的二手 PRD。本项目深度践行 **FDE（Forward Deployed Engineer）** 敏捷模式：
- **直接对接公司各级需求方（Direct-to-Stakeholders）**：直接面向公司管理层与各业务中心负责人，一手获取未经剪裁的公司原始经营诉求与管控目标，做到需求理解“零中间商损耗”；
- **开发直接始于原始需求（Demand-First Engineering）**：许多核心模块在立项时并没有现成的产品原型与规整文档，而是直接从公司的业务卡点与管理痛点出发，由工程师主导推演完成“需求拆解 ➔ 业务状态机建模 ➔ 交互抽象 ➔ 架构设计”；
- **技术主动反哺管理决策（Tech Drives Decision）**：无论是前文详述的“自研树状工作流引擎”，还是“期初库存阶梯式批量校验”、“uni-app 移动现场作业打卡”，均是在直接承接公司诉求后由技术自主建议并主导架构落地，而非被动等待需求排期；
- **代码即原型敏捷共识（Code-as-Prototype）**：依托规范的 Monorepo 抽象组件库与 UnoCSS 快速装配能力，跳过冗长低效的静态低保真画图流程，直接以高保真可交互的系统原型与公司决策层敏捷对齐，大幅缩短系统从立项到投产的试错周期。

## 💡 难点攻坚与总结

- **自研核心中枢替代传统重型方案**：面对企业流程流转与业务表单强绑定的刚需，打破教条，主动舍弃维护成本高昂且难以跨端适配的传统 BPMN，基于树状 AST 独立设计并交付了轻量卡片式工作流引擎，兼顾了极简的人机交互体验、移动端无缝跨端还原与纳秒级安全条件求值。
- **超复杂数据联动与状态流转**：从销售合同发起，经由预算、概算、采购、物料出库到最终验收结项，业务链路极长且前后状态高度依赖。通过设计清晰的状态机模型与数据映射，保障了数十张业务单据在不同流转阶段的严谨一致。
- **FDE 复合工程素养与端到端交付力**：直接对接公司战略与业务需求，以 FDE 姿态横跨“公司原始需求梳理 ➔ 业务模型抽象 ➔ 架构基建 ➔ 多端联调发布”，单人全盘抗住 16+ 个核心业务模块从 0 到 1 的高质量落地，展现了卓越的业务前瞻性、全局系统架构视野与极强的不确定性攻坚能力。
